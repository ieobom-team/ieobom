# 이어봄 (Ieobom) 디자인 시스템 가이드라인 (`DESIGN.md`)

> **문서 상태**: Draft (초기 UI 와이어프레임 및 러프 목업 기반 추출)  
> **기준 컨텍스트**: 주간보호센터 현장 근무자(요양보호사·간호조무사·사회복지사·운전원·센터장)를 위한 AI 인계 및 후속 업무 도구  
> **디자인 원칙**: 따뜻하고 차분한 온기, 군더더기 없는 명확성, 높은 가독성과 현장 친화적 터치 인터랙션  
> **적용 단계**: **1단계 — 기존 화면 흐름·로직은 유지하고 색상·컴포넌트 리스킨을 먼저 끝낸다.** (§12 적용 전략)

## 1. Overview (디자인 개요 및 철학)

**이어봄의 인터페이스는 '바쁜 돌봄 현장에서 한눈에 읽히고 즉시 터치할 수 있는 따뜻하고 정갈한 도구'를 지향합니다.**

주간보호센터 근무자는 돌봄 중 컴퓨터 앞에 오래 앉아 있을 수 없습니다. 한 손에는 어르신을 부축하거나 이동 중인 상태에서 모바일 기기를 다루는 경우가 많고, 근무자의 연령대(50~60대 비율 높음)를 고려할 때 일반적인 복잡한 SaaS 대시보드나 차가운 다크 테마는 적합하지 않습니다.

이어봄의 시각 언어는 다음 세 가지 핵심 축을 기반으로 구성됩니다:

1. **온기와 편안함 (Warm & Grounded)**  
   차가운 백색(#FFFFFF) 대신 부드러운 웜 베이지(`{colors.canvas}` — #F4EFE7)를 기본 배경으로 사용하고, 활력과 주의를 동시에 환기하는 테라코타 오렌지(`{colors.primary}` — #D46641)를 단일 핵심 포인트로 활용합니다.
2. **높은 가독성과 직관적 위계 (High Legibility & Clear Hierarchy)**  
   작은 폰트(12~14px)의 빽빽한 배치를 피하고 기본 본문 크기를 15~17px 이상으로 넉넉하게 설정합니다. 인계 카드와 업무 목록은 상단에 굵고 명확한 어르신 성함과 안전 주의 뱃지를 두어 1초 안에 맥락을 파악할 수 있도록 돕습니다.
3. **직관적이고 단순하고 확실하게**  
   중요도가 높은 항목은 한눈에 인지할 수 있도록 명확한 UI 요소를 제공합니다.

> **참고**: 본 가이드라인은 초기 UI 와이어프레임(37종 목업)의 공통 속성을 기반으로 한 큰 틀의 디자인 원칙입니다. 실제 기능 구현 및 세부 화면 작업 시 도메인 맥락에 맞춰 유연하게 적용할 수 있습니다.

## 2. Interaction Principles (현장 사용 원칙)

> **이 섹션이 색상보다 앞에 오는 이유**: 이어봄의 화면이 왜 그렇게 생겼는지에 대한 근거가 여기에 있다.
> 색·간격·컴포넌트 선택이 이 원칙과 충돌하면 **원칙을 따른다.**

요양보호사는 어르신을 부축하다 말고, 이동 중에, 한 손으로 화면을 만진다. **예뻐서 쓰는 도구가 아니라 빨라서 쓰는 도구**여야 한다. 아래 다섯 가지는 그 "빠름"을 실제 판단 기준으로 옮긴 것이다.

### 2.1. 논스톱 (Non-stop Flow)

핵심 플로우(특이사항 남기기 → 인계 카드 확인 → 후속 업무 처리)는 **시작부터 끝까지 흐름이 끊기지 않아야 한다.**

- 어떤 화면에서든 **핵심 행동에 1탭 안에 닿는다.** (하단 탭바 또는 화면 하단 고정 CTA)
- **저장·제출·삭제 외에는 확인 모달을 띄우지 않는다.** 확인 모달은 클릭 1회 추가이자 흐름 단절이다.
- 처리 중에도 화면을 비우지 않는다. 전체 화면 스피너 대신 **자리를 지키는 스켈레톤이나 인라인 표시**를 쓴다.
- 실패가 흐름을 되감지 않게 한다. 오프라인·전송 실패는 화면을 되돌리지 말고 **그 자리에 상태만 알린다.** (예: "연결되면 자동으로 보냅니다")

### 2.2. 화면 분량 — 스크롤과 클릭 사이 (Screen Budget)

**"한 화면 = 한 목적, 한 목적 안의 선택은 한 화면에 모아서."**

| 구분 | 규칙 |
|---|---|
| **하한 (너무 잘게 쪼개지 않기)** | 선택지 하나만 놓고 화면을 넘기지 않는다. 서로 붙어 있는 짧은 선택(어르신 · 시점 · 입력 방식)은 **한 화면에 묶는다.** |
| **상한 (너무 길지 않기)** | 입력·상세 화면은 세로 **2 뷰포트 이내**를 목표로 한다. 그보다 길어지면 접기(아코디언)나 단계 분리를 검토한다. |
| **목록 화면 예외** | 목록은 스크롤을 허용한다. 단 무한정 늘리지 말고 **필터 칩("전체 / 검토 필요 / 안전 항목")으로 먼저 줄인다.** |

- 입력형 화면은 **묶고**, 조회형 화면은 **스크롤을 허용한다.**
- "2 뷰포트"는 금지선이 아니라 **목표치**다. 넘어갈 때 한 번 이유를 생각하라는 뜻이다.

### 2.3. 자동 진행 대신 인라인 확장 (Progressive Disclosure, not Auto-advance)

선택할 때마다 **화면을 자동으로 넘기지 않는다.** 대신 **같은 화면에서 아래로 자라나게** 한다.

```
어르신     [ 김박사 ▾ ]                ← 고르면
입력 시점  [ 오전 돌봄 ▾ ]             ← 아래에 나타난다. 고르면
입력 방식  ( 음성 ) ( 텍스트 ) ( 체크 )  ← 아래에 나타난다. 고르면
                  ● 녹음 시작           ← 아래에 나타난다
```

- **왜 화면 자동 전환을 쓰지 않는가**: 잘못 눌렀을 때 이미 다음 화면이라 회복 비용이 크고, 방금 무엇을 골랐는지 화면에서 사라져 확인할 수 없다. 고령 사용자에게 특히 불리하다.
- **인라인 확장의 이점**: 클릭 수는 같지만 전환 대기 · 맥락 상실 · 뒤로가기 혼란이 없고, 고른 값이 위에 남아 **즉시 되돌려 고칠 수 있다.**
- **"자동"은 스크롤까지만**: 선택 후 다음 영역으로 부드럽게 스크롤 이동하는 정도는 좋다. 화면 자체를 바꾸지는 않는다.
- 단계 분리가 불가피할 때(예: 녹음 → 결과 확인)는 **뒤로 가면 입력값이 그대로 남아 있어야 한다.**

### 2.4. 클릭은 기본값으로 줄인다 (Smart Defaults)

가장 확실하게 빨라지는 방법은 UI를 바꾸는 것이 아니라 **애초에 고를 필요를 없애는 것**이다.

- **본인/대리**: 세션의 본인이 기본값. "다른 사람 대신 입력"은 눈에 띄되 보조 링크로 둔다.
- **입력 시점**: 현재 시각으로 오전/오후 돌봄을 자동 선택하고, 틀리면 바꿀 수 있게만 해 둔다.
- **입력 방식**: 마지막에 쓴 방식을 기억한다. 초기 기본값은 음성.
- 기본값은 **항상 눈에 보이고 항상 바꿀 수 있어야 한다.** 화면에 드러나지 않는 자동 선택은 쓰지 않는다.

### 2.5. 직관성 — 찾기 어렵지 않게 (Findability)

- **라벨은 기능명이 아니라 행동어로**: "특이사항 등록 관리"가 아니라 **"특이사항 남기기"**, "업무 조회"가 아니라 **"내 할 일"**.
- **아이콘 단독 사용 금지.** 아이콘은 항상 텍스트 라벨과 함께 쓴다.
- **하단 탭은 3개를 기본**으로 한다. (현장 홈 · 인계 카드 · 오늘의 업무) 탭이 늘면 터치 폭과 라벨 가독성이 함께 줄어든다.
- **같은 것은 같은 자리에**: 주요 CTA는 화면 하단, 뒤로가기는 좌상단, 상태 뱃지는 카드 좌상단으로 고정한다.
- **되돌릴 수 있게**: 파괴적 행동(삭제)에만 확인 모달을 쓰고, 나머지는 취소·수정 경로를 남기는 쪽을 택한다.

## 3. Colors (색상 체계)

> **기준 톤앤매너**: 따뜻한 미색 캔버스 + 테라코타 오렌지 포인트 + 반투명 화이트 카드 + 고대비 차콜 텍스트

```
[ 배경 Canvas ]       [ 브랜드/포인트 Primary ]     [ 서피스 Surface ]
  #F4EFE7 (미색)            #D46641 (테라코타)        rgba(255,255,255,0.5~0.8)
  
[ 메인 텍스트 Ink ]     [ 보조 텍스트 Muted ]        [ 상태/완료 Success ]
  #1A1A1A (차콜블랙)         #606060 (중간 회색)          #16A34A (차분한 초록)
```

### Brand & Primary Accent
- **Primary Orange** (`{colors.primary}` — `#D46641`)  
  서비스의 유일한 메인 브랜드/액션 컬러. 주요 CTA 버튼("특이사항 남기기", "등록 완료", "제출하기", "대리 완료"), 활성 탭 인디케이터, 미처리 및 검토 필요 강조 숫자, 안전 주의 뱃지 텍스트/아이콘에 일관되게 사용됩니다.
- **Primary Tint / Soft** (`{colors.primary-soft}` — `#F7EDE8` 또는 `rgba(212, 102, 65, 0.12)`)  
  안전 주의 뱃지 배경, 음성 녹음 진행 링의 소프트 배경, 역할 뱃지(센터장/요양보호사 등)의 은은한 배경으로 사용되어 강한 오렌지와 조화를 이룹니다.

### Canvas & Surfaces
- **Warm Canvas** (`{colors.canvas}` — `#F4EFE7`)  
  전체 애플리케이션의 기본 캔버스 배경. 종이의 질감과 온기를 주는 라이트 웜 베이지 톤입니다.
- **Card Surface Translucent** (`{colors.surface-card}` — `rgba(255, 255, 255, 0.50)` ~ `rgba(255, 255, 255, 0.80)`)  
  배경 위에 얹히는 인계 카드, 통계 요약 박스, 입력 폼 영역의 기본 서피스. 반투명 화이트로 캔버스 톤을 부드럽게 비치게 하여 깊이감을 부여합니다.
- **Modal / Sheet Surface** (`{colors.surface-modal}` — `#FFFFFF`)  
  중앙 팝업 모달, 바텀 시트, 드롭다운 메뉴 등 명확한 분리가 필요한 플로팅 레이어에 사용하는 순수 화이트 서피스.
- **Dark Utility Button** (`{colors.surface-dark}` — `#333333` 또는 `#2C2C2E`)  
  "관리자로 입장", "현장 근무자로 입장", "녹음하기/정지", "인계 카드로 돌아가기" 등 묵직하고 안정적인 보조·기능성 액션 버튼에 사용되는 다크 차콜.

### Text & Icons
- **Ink Primary** (`{colors.text-primary}` — `#1A1A1A` / `#000000`)  
  헤드라인, 어르신 성함, 메인 필드 레이블, 선택된 항목 등 주요 텍스트의 선명한 시각적 중심.
- **Ink Secondary / Muted** (`{colors.text-secondary}` — `#606060`)  
  부가 설명, 원문 발화 텍스트, 시간/작성자 정보, 미입력 안내 문구 등 보조 텍스트.
- **Ink Tertiary / Placeholder** (`{colors.text-tertiary}` — `#8E8E93` / `#9E9E9E`)  
  입력 필드 플레이스홀더, 비활성 아이콘, 미선택 탭 레이블.
- **Text On Dark / Primary** (`{colors.text-on-action}` — `#FFFFFF`)  
  오렌지 Primary 버튼, 다크 버튼, 완료 뱃지 내부 텍스트.

### Borders & Hairlines
- **Border Card** (`{colors.border-card}` — `#C9C9C9` 또는 `rgba(0, 0, 0, 0.12)`)  
  카드, 인풋 필드, 지표 박스의 1px 외곽선. 과도하게 도드라지지 않으면서 영역을 단정하게 정리합니다.
- **Border Divider** (`{colors.border-divider}` — `#E2DDD5`)  
  헤더 하단, 리스트 아이템 간의 얇은 구분선.

### Status & Feedback
- **Status Attention / Incomplete** (`{colors.status-attention}` — `#D46641`)  
  검토 필요, 미처리, 기한 초과, 지연 건수 등 근무자의 즉각적인 확인이 필요한 상태.
- **Status Done / Success** (`{colors.status-success}` — `#16A34A` 또는 `#2E7D32`)  
  검토 완료, 업무 처리 완료, 정상 등록 완료 상태를 나타내는 신뢰의 그린.
- **Status Neutral / Sub Action** (`{colors.btn-neutral-bg}` — `#E5E5EA` / `#E0E0E0`, 텍스트 `#1A1A1A`)  
  "취소", "텍스트로 입력하기", "새로 작성하기", "복사" 등 보조 버튼에 사용되는 연한 그레이.

## 4. Typography (타이포그래피)

### Font Family
- **기본 폰트**: `Pretendard, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Noto Sans KR", sans-serif`
- 가독성이 우수하고 자간과 숫자의 렌더링이 깔끔한 현대적인 고딕 계열을 사용합니다.

### Hierarchy (타이포그래피 위계)

| 토큰 | 크기 (Size) | 굵기 (Weight) | 행간 (Line Height) | 주요 용도 |
|---|---|---|---|---|
| `{typography.display-stat}` | 24px ~ 28px | Bold (700) | 1.2 | 지표 요약 건수 ("2건", "11건"), 타이머 카운트다운 |
| `{typography.title-screen}` | 20px ~ 22px | Bold (700) | 1.3 | 화면 최상단 타이틀 ("오늘의 인계 카드", "특이사항 입력") |
| `{typography.title-section}` | 17px ~ 18px | Bold (700) | 1.4 | 섹션 헤더 ("어르신별 인계 카드", "후속 업무", "새 알림") |
| `{typography.title-card}` | 17px ~ 18px | SemiBold (600) | 1.4 | 어르신 성함 ("강별철 어르신", "김순례 어르신"), 모달 제목 |
| `{typography.body-lead}` | 15px ~ 16px | Medium (500) | 1.5 | 카드 요약 내용, 상태 변화/조치 타이틀, 알림 헤드라인 |
| `{typography.body-regular}` | 14px ~ 15px | Regular (400) | 1.55 | 원문 근거 내용, 상세 설명, 인풋 텍스트 |
| `{typography.caption}` | 12px ~ 13px | Regular/Medium | 1.4 | 날짜/시각, 작성자 직종 ("오늘 09:14 · 물리치료사"), 출처 |
| `{typography.button-primary}` | 16px ~ 17px | SemiBold (600) | 1.0 | 주요 액션 버튼 라벨 ("특이사항 남기기", "대리 완료") |
| `{typography.button-sub}` | 14px ~ 15px | Medium (500) | 1.0 | 칩 필터 라벨, 작은 복사 버튼, 취소 버튼 |

### 타이포그래피 핵심 원칙
1. **노안 및 현장 조작 고려 (Body 14~16px)**  
   일반적인 웹의 12~13px 본문은 지양하고, 본문 텍스트는 14~16px, 제목은 18~22px로 큼직하게 유지합니다.
2. **숫자의 시각적 분리 (Bold Metrics)**  
   "3건", "오늘 중", "14:30"과 같은 기한 및 건수 숫자는 굵은 웨이트와 오렌지 컬러로 텍스트 사이에서 즉시 도드라지게 처리합니다.
3. **군더더기 없는 문장 (Clear & Concise Copy)**  
   현장 근무자가 짧은 시간에 읽고 이해할 수 있도록 명확하고 간결한 안내 문구와 레이블을 사용합니다.

## 5. Layout & Spacing (레이아웃 및 간격)

### Base Spacing Scale (8px 기준)
- `{spacing.xxs}`: 4px (미세 인라인 간격, 아이콘-텍스트 간격)
- `{spacing.xs}`: 8px (뱃지 패딩, 작은 칩 간격)
- `{spacing.sm}`: 12px (컴팩트 카드 패딩, 인풋 필드 간격)
- `{spacing.md}`: 16px (기본 카드 내부 패딩, 컨테이너 좌우 여백)
- `{spacing.lg}`: 20px ~ 24px (카드 간의 수직 간격, 섹션 간 여백)
- `{spacing.xl}`: 32px ~ 40px (화면 헤더와 콘텐츠 간의 큰 여백)

### Grid & Containers
- **모바일 뷰포트 (기준)**: 폭 360px ~ 430px (모바일 웹 화면 기준 최대 480px 중앙 정렬 컨테이너)
- **태블릿/데스크톱 뷰포트 (관리자용)**: 최대 1024px ~ 1200px (대시보드 그리드 2~3열 확장)
- **화면 좌우 기본 마진**: `16px ~ 20px`

### 터치 타겟 & 인체공학 (Touch Targets)
- **주요 버튼 높이**: 최소 `48px ~ 54px` (한 손 엄지 터치 최적화)
- **보조 버튼/칩 높이**: 최소 `36px ~ 42px`
- **하단 내비게이션 바 높이**: `60px ~ 68px` (하단 세이프 에어리어 포함)
- **체크박스/토글/라디오**: 터치 영역 최소 `44px × 44px` 이상 확보

## 8. Components (주요 컴포넌트 패턴)

### 8.1. Navigation & Header
- **Top Bar (화면 헤더, 2행 구조)**
  - **1행**: 좌측에 서비스 로고(`이어봄`, 항상 고정 노출 — 뒤로가기 유무와 무관). 우측에 이름/역할 칩 → 본인 바꾸기 → PIN 설정 → 알림 종 아이콘 순서로 배치.
  - **2행 (화면 제목이 있을 때만 노출)**:
    - 뒤로가기가 있는 화면: `‹ 제목` 형태로 표시하며, 줄 전체가 클릭 가능한 뒤로가기 링크/버튼이 된다. 뒤로가기 레이블은 화면에 표시하지 않고 `aria-label`로만 제공한다.
    - 뒤로가기가 없는 화면: `‹` 없이 제목만 클릭 불가능한 일반 텍스트로 표시한다.
    - 제목도 없으면 2행 자체를 렌더링하지 않는다.
  - 좁은 화면에서 뒤로가기·로고·제목이 한 줄에 몰려 잘리는 문제를 막기 위해 1행(로고+세션 정보)과 2행(뒤로가기+제목)을 분리한 구조다. (§2.2 Screen Budget · §2.5 같은 것은 같은 자리에)
- **Bottom Navigation Bar (하단 탭 바)**  
  - 3개 탭 구조를 기본으로 하며, 세부 항목은 유연하게 구성합니다.
  - 활성 탭: 상단에 2px 테라코타 오렌지 라인 인디케이터 + 오렌지 원형 아이콘 + 오렌지 텍스트
  - 비활성 탭: 연한 그레이 원형 아이콘 + 다크 그레이 텍스트
  - iOS 홈 인디케이터 등 세이프 에어리어와 겹치지 않도록 `env(safe-area-inset-bottom)` 만큼 하단 패딩을 두며, 이 값이 실제로 적용되려면 `viewport-fit=cover`가 viewport meta에 있어야 합니다.

### 8.2. Action Buttons (버튼)
- **Primary Action Button (오렌지 CTA)**  
  배경 `#D46641`, 텍스트 `#FFFFFF`, 높이 50~54px, 둥근 모서리 10~12px. 화면 최하단 고정 또는 폼 하단 전체 너비로 사용.
- **Secondary / Ghost Button (취소/보조)**  
  배경 `#E5E5EA` 또는 투명 배경 + 1px 보더, 텍스트 `#1A1A1A`.
- **Dark Utility Button (다크 버튼)**  
  배경 `#333333`, 텍스트 `#FFFFFF`. 초기 역할 입장 화면이나 녹음 제어 버튼에 활용.
- **Inline Copy Button (문구 복사 버튼)**  
  배경 `#E5E5EA`, 텍스트 `#1A1A1A`, 패딩 8px × 16px, 둥근 모서리 8px.

### 8.3. Cards & Tiles (카드)
- **인계 요약 카드 (Handover Card)**  
  - 상단: `[안전/일반]` 카테고리 뱃지 + `[검토 필요/검토 완료]` 상태 뱃지
  - 본문: 굵은 어르신 성함 + 2줄 이내의 상태 변화/조치 요약
  - 하단: 후속 업무 유무 및 당일 시각 기한, "원문 근거 확인 가능" 링크
- **통계 요약 지표 박스 (Metric Box Grid)**  
  화면 상단에 3~4열 그리드로 배치. 상단에 라벨("전체", "미처리", "완료", "기한 초과"), 중앙에 큼직한 건수 숫자(오렌지/차콜).
- **보조 정보 박스 (Reference Box)**  
  카드 하단에 배치되는 추가 정보 영역. 인용구 텍스트나 보조 액션 버튼(예: 음성 재생 버튼 등)을 담을 수 있는 깔끔한 컨테이너입니다.

### 8.4. Forms & Inputs (입력 요소)
- **어르신/시점 드롭다운 (Select Box)**  
  높이 48px, 화이트/반투명 배경, 1px `#C9C9C9` 보더, 우측 화살표 아이콘.
- **입력 방식 세그먼트 칩 및 아웃라인 버튼 (Mode Selector / Outline Pill)**  
  선택된 항목은 오렌지 배경과 화이트 텍스트로, 미선택 항목은 옅은 윤곽선(Outline) 형태로 구성하여 다양한 다중/단일 선택 UI에 유연하게 활용합니다.
- **토글 스위치 (Toggle Switch)**  
  상태 변경 등 즉각적인 On/Off 피드백이 필요한 곳에 적용합니다.
- **음성 녹음 UI (Voice Recording Box)**  
  중앙의 커다란 오렌지색 원형 마이크/정지 버튼 (직경 80px), 녹음 진행 시간 타이머 ("00:09"), "녹음 중... 말씀이 끝나면 정지 버튼을 눌러주세요" 안내 문구.
- **다중 선택 체크리스트 (Checkbox Grid)**  
  여러 항목을 동시에 선택할 수 있음을 인지하기 쉽도록 사각형 체크박스를 주로 사용하며 터치 영역을 크게 확보합니다.

### 8.5. Modals, Notifications & Empty States (팝업, 알림 및 빈 화면)
- **공통 모달 버튼 규칙**: 사용자 혼선을 막기 위해 모달 하단 버튼은 '취소/닫기' 등 보조 액션을 연한 회색(좌측)으로, '확인/완료/삭제' 등 주요 실행 액션을 메인 오렌지색(우측)으로 일관되게 배치합니다. (예: 대리 완료 확인, 명단 삭제 모달 등)
- **빈 화면 및 에러 (Empty / Error State)**: 음성 인식 실패나 데이터가 없는 화면의 경우, 직관적인 중앙 정렬 아이콘과 안내 텍스트를 제공하고 사용자가 바로 취할 수 있는 대안 액션 버튼(예: 다시 시도, 텍스트 입력)을 명확히 제시합니다.
- **하원 전 미처리 브리핑 알림**: "[!] 미처리 항목 3건이 하원 전까지 확인이 필요합니다." 경고 박스 및 브리핑 진입 버튼.

## 9. Do's and Don'ts (디자인 원칙 및 금기 사항)

### Do (권장 사항)
- **따뜻한 미색 캔버스 유지**: 배경은 항상 `#F4EFE7`을 사용하여 현장의 차분함과 온기를 지킵니다.
- **중요 항목 시각적 강조**: 중요한 카테고리(안전 등)의 항목은 오렌지 테두리나 뱃지 등의 시각적 요소를 통해 명확히 식별할 수 있게 디자인합니다.
- **명확한 정보 위계 유지**: 카드 내의 핵심 내용과 보조/참고 정보(버튼, 인용구 등)가 시각적으로 섞이지 않도록 여백과 폰트 크기로 구분합니다.
- **충분한 터치 타겟(48px 이상)**: 이동이 잦고 장갑을 끼거나 손이 바쁜 현장 근무자를 위해 버튼과 탭 영역을 넉넉하게 잡습니다.
- **미처리/완료 단순 상태 관리**: 현장의 혼선을 방지하기 위해 업무 상태는 '미처리'와 '완료' 2단계로 단순화합니다.

### Don't (금지 사항)
- **차가운 다크 테마 남용 금지**: 보조 유틸리티 버튼 외에 전체 캔버스를 어두운 블랙이나 네온 컬러로 구성하지 않습니다.
- **과도한 그라디언트 및 화려한 섀도우 배제**: 장식적인 네온 그라디언트나 짙은 그림자 대신 깔끔한 보더와 투명도를 활용합니다.
- **복잡한 다단계 상태나 세부 권한 UI 도입 금지**: MVP 범위에 맞추어 복잡한 로그인/권한 구조 대신 직관적인 역할/본인 선택(선택형 PIN) 수준으로 간결하게 유지합니다.
- **작은 글씨(13px 이하) 남용 금지**: 현장 연령층과 시인성을 저해하는 작은 본문 폰트 사용을 피합니다.
- **복잡한 안내문 중첩 금지**: 사용성을 해칠 수 있는 지나치게 길거나 중첩된 경고/안내 문구 배치를 피하고, 필수적인 메시지만 간결하게 제공합니다.

## 11. Known Gaps & Design Flexibility Notes (유연성 가이드)

> **디자이너 및 개발자 참고 사항**:

## 12. Rollout Strategy (적용 전략 — 사람·에이전트 공통)

> 이 섹션은 "무엇을 디자인할까"가 아니라 **"어떤 순서로 손댈까"**에 대한 팀 합의다.
> 디자인 작업을 시작하는 사람(에이전트 포함)은 이 순서를 먼저 확인한다.

### 12.1. 와이어프레임의 지위 — 참고용이다

`0818Tue-ui/`(37종)와 `0818Tue-ui-2/`의 PNG는 기능 흐름과 정보 구조의 방향을 잡기 위한 **러프 와이어프레임(Rough Wireframe)**이다.

- 구현이 와이어프레임을 그대로 따를 의무는 없다. **점진적으로 참고해 비슷하게 맞추되, 화면마다 조금씩 달라질 수 있다.**
- 와이어프레임과 현재 구현이 다를 때 **자동으로 와이어프레임이 이기지 않는다.** §2 원칙에 더 부합하는 쪽을 택한다.
- 와이어프레임에만 있고 구현에 없는 화면·기능은 **만들 근거가 되지 않는다.** 기능의 근거는 Manyfast와 GitHub Issue다. (`AGENTS.md` 개발 명세 우선순위)

### 12.2. 1단계 — 리스킨 우선 (현재 단계)

**기존 화면 흐름과 로직은 그대로 둔 채, 색상 · 타이포 · 컴포넌트 외형만 이 문서에 맞춘다.**

- 대상: 컬러 토큰, 폰트 위계, 간격, 곡률, 버튼 · 카드 · 인풋 · 탭바 · 헤더의 외형
- **손대지 않는 것**: 라우트 구조, 입력 단계(step) 구성, API 계약, Manyfast 명세, 상태 관리 로직
- 판단 기준 한 줄: **"이 변경이 컴포넌트의 생김새만 바꾸는가?"** 아니라면 1단계 범위 밖이다.
- 기존 구현을 최대한 살린다. **화면을 새로 만들기보다 있는 화면을 다듬는다.**

### 12.3. 2단계 — UI/UX 보완 (전 화면 리스킨 완료 후)

리스킨이 전부 끝난 뒤, §2 원칙에 비추어 불편한 지점을 **조금씩** 고친다.

- 예상 후보: 특이사항 입력의 단계 구성(§2.3 인라인 확장), 기본값 자동 선택(§2.4), 화면 길이 조정(§2.2)
- 이 단계의 변경은 사용자 동작을 바꾸므로 **Manyfast 갱신 필요 여부를 먼저 판단**한다. (`AGENTS.md` 승인 경계 C)

### 12.4. 1단계에서도 기능을 고쳐도 되는 예외

**누가 봐도 명확한 불편이나 개선점이면 1단계에서 고쳐도 된다.** 다만 다음을 지킨다.

- 고친 내용과 이유를 **PR 설명에 남긴다.**
- 사용자 동작 · 상태 규칙 · API/JSON 계약이 바뀌면 **Manyfast 갱신 여부를 먼저 판단**한다.
- "명확한"의 기준: 설명 없이 누구나 동의할 수준(오작동, 오탈자, 터치 영역 부족, 글자 잘림, 대비 부족). **판단이 갈리는 개선은 2단계로 미룬다.**
