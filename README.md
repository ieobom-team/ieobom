# 이어봄 (Ieobom)

**잇다 + 돌봄.** 끊기는 정보를 이어서, 다음 사람의 행동까지 잇는다.

> 돌봄 중 한 번 남긴 말이 **공식 기록 · 담당자 할 일 · 처리 확인**까지 이어지는

## 문제

> **돌봄 중에는 기록할 수 없어서, 한 번 말한 정보가 기록·담당자·처리 확인까지 이어지지 않는다.**

주간보호센터는 하루 20~40명(접촉한 13개 센터 평균 31.6명)의 어르신을 요양보호사·간호조무사·사회복지사·물리치료사·운전원이 함께 돌봅니다.  
돌봄 중에는 컴퓨터 앞에 앉을 수 없어 특이사항이 종이 체크표, 단체 대화방, 개인 메모, 화이트보드로 흩어집니다.

```
종이 체크표  ·  단체 대화방  ·  업무일지  ·  개인 메모  ·  화이트보드
```

저희가 만난 근무자들은 이 흩어진 기록을 하원 후 다시 옮겨 적는 데 **매일 30분~1시간**을 쓰고 있었습니다 (접촉한 9명 중 8명이 중복 입력 경험).

더 심각한 문제는 **전화할 만큼 급하지도, 무시할 만큼 사소하지도 않은 '중간 지대의 정보'**입니다.  
송영 취소, 외출 신청, 투약 변경, 면회 시간, 준비물 같은 정보는 단체 대화방에 던져지지만 누가 확인했는지 처리했는지 알 수 없습니다 (9명 중 6명이 최근 한 달 내 인계 누락 사고 경험).

그리고 이 정보에는 **투약 시간, 낙상 위험, 발열, 이동 부축**처럼 어르신의 안전과 직결된 내용이 섞여 있습니다.

<sub>※ 위 수치는 팀이 직접 접촉한 13개 주간보호센터 근무자 인터뷰 및 설문 실측치입니다.</sub>

## 왜 지금인가

병원에서는 인수인계 AI가 이미 투자와 기술이전까지 진행되었습니다.  
하지만 **인력난과 고령화가 더 심각한 요양 현장(주간보호센터)에는 아무도 들어가지 않았습니다.**

기존 장기요양 전산(케어포, 이지케어, 엔젤시스템 등)은 공단 청구와 평가 대비에 맞춰져 있어 기록을 **'저장'**하는 데서 멈추고, **'다음 사람의 행동과 당일 완료 확인'**으로 연결하지 않습니다.

---

## 해결 (핵심 루프 6단계)

이어봄은 이미 말로 하고 있는 인계를 그대로 받아, 다음 사람의 행동과 전산 기록까지 끊김 없이 잇습니다.

```
① 한 번 남기기 → ② 어르신 카드 정리 → ③ 담당·기한 자동 배정 → ④ 실시간 알림·수임 → ⑤ 하원 브리핑·완료 → ⑥ 문구 복사·출력
```

| | 기능 | 하는 일 |
|---|---|---|
| **①** | **현장 특이사항 한 번 남기기** | 음성 · 짧은 텍스트 · 체크 중 편한 방식으로 한 번만 남깁니다. 큰 글씨와 큰 버튼의 고령 친화 UI를 지원하며, 네트워크가 불안정해도 기기 임시 저장 후 자동 재전송합니다. |
| **②** | **어르신별 카드 & 추천 액션 칩** | 여러 어르신이 섞인 발화를 어르신별로 나누고 **상태변화 · 조치 · 다음행동**으로 구조화합니다. AI 추천 액션 칩을 탭해 원클릭으로 조치를 채울 수 있으며, 원문 근거와 원본 음성을 상시 확인합니다. |
| **③** | **담당 직종 · 당일 기한 자동 추론** | 도메인 분업 규칙(투약→간호조무사, 송영→운전원, 상담→사회복지사 등)을 기반으로 담당 직종과 당일 시각(HH:MM) 기한을 자동 제안합니다. |
| **④** | **실시간 알림 & 공동 업무 수임** | 배정 즉시 앱 내 알림(3초 폴링 배지)과 개인 기기 웹 푸시(Web Push)로 전달됩니다. 직종 배정 업무는 **'내가 처리할게요'**를 눌러 담당자로 즉시 확정됩니다. |
| **⑤** | **하원 미처리 브리핑 & 대리 완료** | 어르신이 당일 귀가하는 구조에 맞춰 하원 시점에 오늘 미처리 건수를 한눈에 확인합니다. 관리자가 수행자 확인 후 대리 완료 처리하여 루프를 닫습니다. |
| **⑥** | **기록 문구 복사 & 파일 출력** | 기존 전산에 붙여넣을 **전산 기록 문구**와 보호자용 **전달 문구**를 생성합니다. 텍스트 · 마크다운 · 엑셀(`.xlsx`) · 워드(`.docx`) 파일 다운로드를 지원합니다. |

## AI가 하는 일 / 절대 안 하는 일 (안전 및 신뢰 원칙)

| ✅ 하는 일 | ⛔ 절대 안 하는 일 |
|---|---|
| 뒤섞인 발화를 **어르신별로 분리** | 의료적 판단 · 진단 · 투약 권고 |
| 한 문장에서 **상태변화 / 조치 / 다음행동** 구분 | **근거 없는 정보 지어내기 (Hallucination)** |
| 도메인 분업 지식 기반 **담당 직종 및 당일 시각 기한 제안** | 음성 어투나 감정 기반 긴급도 판정 |
| AI 발화 맥락 기반 **추천 액션 칩(2~3개)** 제시 | 직원 검토 없이 보호자에게 자동 발송 |
| 안전 항목(낙상·발열·식사저하·투약변경) **자동 판정 및 상단 우선 배치** | 상시 녹음 (세션 단위 녹음만 지원, 5분 제한) |
| **어르신 실명 사전 가명처리** (LLM에 실명 미전송) | 기존 ERP 서식에 맞춘 억지 자동 매핑 |

> 🔒 **근거 원문이 없으면 항목을 만들지 않습니다.**  
> AI 출력은 Function Calling으로 JSON Schema를 엄격히 강제하며, 모든 구조화 항목에 원문 근거가 연결됩니다.  
> 뉘앙스는 어조 추정 대신 **원본 음성 재생**으로 확인합니다.

## 현장 친화적 보안 & 식별 설계

- **어르신 실명 가명처리 (Privacy First)**: 사전 등록된 명단을 바탕으로 LLM 호출 전 룰 기반으로 내부 ID로 치환하고, 화면 표시 시에만 실명으로 복원합니다.
- **선택형 숫자 PIN (공용 태블릿 보호)**: 복잡한 계정 로그인 대신 현장 역할/본인 선택 방식을 유지하되, 공용 기기 오용 방지 및 개인 알림 보호를 위해 직원별 **4~6자리 숫자 PIN** 설정을 지원합니다.
- **개인 기기 웹 푸시 (Web Push)**: HTTPS 환경에서 앱을 닫고 있어도 새 배정 업무를 수신할 수 있습니다. (푸시 알림 본문에는 어르신 실명/건강정보를 포함하지 않습니다.)

## 포지셔닝 & 비즈니스 모델

> **이어봄은 기존 ERP를 대체하는 제품이 아니라, 그 앞단의 인수인계 레이어(Add-on)입니다.**

- **대체하는 것** — 단체 대화방, 개인 메모, 종이 인계장, 화이트보드
- **대체하지 않는 것** — 케어포, 이지케어 등 기존 장기요양 전산 (공단 청구 및 평가 대비)

수익 모델은 기존 전산 요금에 부담 없는 **시설당 월 9,900원 정액 구독**입니다.  
(인터뷰한 예산 결정 참여자 4명의 추가 지출 의향 실측치 기반)

## 기술 스택

| 영역 | 기술 스택 | 설명 |
|---|---|---|
| **Frontend** | React 19, TypeScript, Vite, Tailwind CSS v4 | 반응형 고령 친화 UI, SPA 폴백 |
| **State** | TanStack Query, React Router | 쿼리 캐싱, 3초 폴링 알림 배지, 화면 네비게이션 |
| **Backend** | Java 21, Spring Boot 4.1.0, Spring Data JPA | REST API, AI 오케스트레이션, 업무 라이프사이클 |
| **Database** | MySQL 8.4 LTS, Flyway | 로컬-배포 일관 스키마 관리 (`validate` 모드) |
| **AI / LLM** | OpenAI API (Structured Outputs / JSON Schema 강제) | 발화 분리, 정보 구조화, 추천 칩, 기록 문구 생성 |
| **PWA / Web** | Web Audio API / MediaRecorder, Web Push API | 브라우저 음성 녹음, Service Worker 백그라운드 푸시 |
| **Infra / Deploy** | Docker Compose, Caddy (자동 HTTPS), Gabia Cloud VM | 무설정 SSL 인증서 자동 발급, 리버스 프록시 |
