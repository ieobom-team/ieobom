# sync-manyfast

Notion(논의)과 코드(구현) 사이에서 **Manyfast를 최신 상태로 유지한다.**

## 절차

1. 입력 자료(Notion 회의록, 인터뷰, PR 결과)에서 **확정 사항 / 가설 / 미결정**을 분리한다.
   - 확정 사항만 반영 대상이다.
   - 가설과 미결정은 Manyfast **질문**으로 남긴다. 추측해서 채우지 않는다.
2. Manyfast에 이미 있는 Requirement / Feature / Spec을 확인한다.
3. **중복 생성 대신 기존 항목 업데이트 또는 하위 Spec 추가를 우선한다.**
4. 반영 대상은 **사용자 동작 · 정책 · 데이터 계약이 바뀌는 내용**으로 한정한다.
   내부 리팩터링, 파일 이동, 스타일 수정은 Manyfast를 건드리지 않는다.
5. 반영 전에 아래를 제시한다.
   - 변경 요약
   - 대상 항목 (ID)
   - 영향받는 Issue
   - 저장할 버전 이름
6. **승인 후** Manyfast를 갱신하고 버전을 저장한다.
7. Notion에는 **반영 사실과 결정 요약만** 남긴다. 명세 본문을 복제하지 않는다.

## 버전 규칙

- P0 기능 구현 시작 전 `v0.1-core-flow`를 저장한다.
- 데모 흐름 또는 사용자 동작이 바뀌면 다음 버전을 저장한다.
- 단순 문구 수정이나 내부 구현 변경만으로는 버전을 저장하지 않는다.
- 저장한 버전 이름은 관련 Issue와 PR에 기록한다.

## 경계

- Notion 회의록을 그대로 명세로 옮기지 않는다. **확정 여부를 먼저 가른다.**
- Manyfast 원문을 `docs/`에 복제하지 않는다. `docs/contracts/`에는 코드와 함께 바뀌는 기술 계약만 둔다.
